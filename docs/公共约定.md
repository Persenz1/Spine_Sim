# 公共约定

本文件汇总所有模块共同遵守的约定。理解这些约定后，再阅读地形、几何、单刺和阵列实现。

## 1. 公共基础模块

| 文件 | 作用 |
|---|---|
| `core/versions.py` | 定义参与 case/result identity 的语义版本 |
| `core/units.py` | 将显式单位转换为 SI |
| `core/frames.py` | 定义 frame metadata 和带完整标签的 wrench |
| `core/identity.py` | canonical JSON、稳定哈希和确定性 ID |
| `core/config.py` | case 和 campaign 配置 |
| `core/states.py` | 物理、数值、模型、运行状态和物理事件 |
| `core/errors.py` | 异常类别和运行错误归类 |
| `parameters/registry.py` | 参数、protocol、seed、旧输入迁移和来源状态 |
| `runtime/backend.py` | CPU/CUDA 能力发现和最小运行环境探测 |
| `io/schema.py` | canonical 物理结果 metadata 和字段校验 |
| `io/files.py` | 原子文件写入、文件 SHA-256 和 UTC 时间 |

## 2. 单位

内部物理量统一使用 SI：

- 长度：m；
- 角度：rad；
- 力：N；
- 力矩：N·m；
- 刚度：N/m 或对应广义刚度；
- 应力/模量：Pa；
- 时间：s；
- 速度：m/s。

`to_si` 接受裸 SI 数值，或 `{"value": 数值, "unit": 单位}`。支持：

| 维度 | 显式单位 |
|---|---|
| 长度 | `m`、`mm`、`um`、`µm`、`nm` |
| 角度 | `rad`、`deg` |
| 力 | `N` |
| 刚度 | `N/m` |
| 压力 | `Pa`、`MPa`、`GPa` |
| 时间 | `s` |
| 速度 | `m/s`、`mm/s` |

通用 campaign 的 `parameters` 是开放映射，runner 不会自动为它转换单位。配置作者或 campaign 生成器必须先完成单位归一化，再构造 `BaseCaseSpec`；case callable 此时只能验证并拒绝非 canonical 输入，因为 case identity 已经由 `parameters` 建立。

## 3. 坐标和方向

宏观墙面使用右手坐标系：

- \(+x\)：主要搜索和抗拖方向；
- \(+y\)：墙面内横向；
- \(+z\)：由墙体指向机器人，即离墙方向；
- 压紧墙面为 \(-z\)，剥离墙面为 \(+z\)。

刺轴 `axis_root_to_tip` 从安装出口/根部指向球尖中心。以 pitch、yaw 表示：

\[
\mathbf e_s=
[\cos\beta\cos\psi,\ \cos\beta\sin\psi,\ \sin\beta].
\]

旧工程中“朝墙为正”的角度迁移为：

\[
\text{pitch\_rad}=-\operatorname{deg2rad}(\alpha_{old}),
\qquad
\text{yaw\_rad}=\operatorname{deg2rad}(\beta_{yaw,old}).
\]

## 4. 力与作用对象

必须区分：

1. 墙面对针的接触力；
2. 针作用在墙上的反力；
3. 根部/悬架对针的力；
4. 针传给背板的支撑力。

准静态平衡下，墙面对针的接触力与针传给背板的支撑力方向相同；针作用在墙上的力与它们反向。

`Wrench` 不只是六个数，还必须带：

- `frame`；
- `reference_point`；
- `acting_on`；
- `exerted_by`；
- `sign_convention`。

点接触在接触点不传递接触偶力。把同一接触力从接触点搬到针根或阵列参考点时，必须加入力臂矩，不能同时叠加“接触点表示”和“根部表示”。

从旧参考点 \(O\) 移到新参考点 \(P\)，传入 \(\mathbf r_{PO}\) 时：

\[
\mathbf M_P=\mathbf M_O+\mathbf r_{PO}\times\mathbf F.
\]

## 5. 几何、接触、挂接和承载

以下概念不能混用：

| 概念 | 含义 |
|---|---|
| 几何候选 | 有限针尖可在不穿透条件下接近某个表面 feature |
| 实际接触 | 间隙闭合且不需要负法向反力 |
| 摩擦可行 | 所需切向力位于摩擦锥内 |
| 稳定挂接 | 局部滑移方向不立即离开安全表面，结构未触发脱离 |
| 有效承载 | 当前实际承担非零宏观载荷并未越过容量/行程边界 |

因此名义刺数、几何候选数、接触数、稳定挂接数和 active 承载数通常不同。

## 6. 状态维度

程序把状态分成四个独立维度：

### 物理状态

```text
SEARCH, CONTACT, STICK, SLIP,
DETACH, REBOUND, HARDSTOP, FAILED
```

`CONTACT` 是 trial 内的瞬时合法性判定，不是可长期提交的 resident state。

### 数值状态

```text
NOT_RUN, CONVERGED, NONCONVERGED, INVALID_RESIDUAL
```

### 模型状态

```text
CLOSED, PARAMETER_UNCLOSED, OUT_OF_SCOPE
```

### 运行状态

```text
PENDING, RUNNING, COMPLETE, CANCELLED, EXECUTION_ERROR
```

数值收敛不代表所有材料参数闭合；到达物理模型边界也不是执行异常。

## 7. 事件

物理事件包括：

```text
CONTACT, CONTACT_REJECT, STICK_START, SLIP_START, RESTICK,
DETACH, REBOUND_START, REBOUND_COMPLETE, REENGAGE,
HARDSTOP, HARDSTOP_RELEASE, MATERIAL_FAILURE
```

`Event` 只记录物理事件，并且必须符合 `ALLOWED_PHYSICAL_TRANSITIONS`，不能通过直接改状态绕过事件。数值、模型和运行结论分别由 `NumericalState`、`ModelState` 和 `RunState` 字段表达，不另设事件包装对象。

## 8. 相对加载坐标

单刺 `BaseMotion.relative_displacement_m` 表示接触约束相对刺根/基座的加载变形。

阵列 `q_C` 是接触约束相对共同背板的六自由度加载坐标。固定墙面时：

\[
\Delta\mathbf q_{backplate}^{phys}=-\mathbf q_C.
\]

程序同时输出 `q_C` 和 `physical_backplate_pose`，不得把二者当成同号变量。

## 9. Trial 与 commit

单刺和阵列都采用不可变状态更新：

```text
accepted state
  → solve(...)
  → trial(result + proposed state)
  → 检查 committable、状态和 revision
  → commit(...)
  → 新 accepted state
```

非收敛、模型边界或过期 revision 的 trial 不得提交。求解函数不会原地修改 accepted state。

## 10. Identity 和版本

当前主要语义版本：

| 对象 | 值 |
|---|---|
| project schema | `2` |
| model schema | `canonical-single-array-1` |
| result schema | `canonical-result-2` |
| solver semantics | `single-array-event-v1` |
| geometry schema | `contact-candidate-2` |
| parameter registry | `canonical-parameters-1` |

`canonicalize` 把 dataclass、容器、Path、枚举和 NumPy 值转成稳定 JSON；`stable_hash` 使用 SHA-256；`identity` 生成 `<kind>_<20位哈希前缀>`。

case ID 包含模块、语义版本、参数哈希、上游哈希和地形/几何版本。语义改变时必须产生新 identity。

## 11. 参数系统

机器参数来源是：

```text
src/spine_sim/parameters/registry.json
```

主要内容：

- 坐标合同；
- 候选设计轴；
- rigid/unilateral spring 安装方式；
- 命名设计生成器；
- paired seed set；
- 运行 protocol；
- 旧设计输入迁移；
- terminal preset 和 selection set；
- 尚未闭合的物理输入。

每个值带 `evidence_status`：

| 状态 | 含义 |
|---|---|
| `frozen_design_semantics` | 冻结的坐标或设计语义 |
| `candidate_design_value` | 候选设计值，不是定型硬件真值 |
| `numerical_protocol` | 运行或离散协议 |
| `legacy_regression` | 保持旧输入/ID 可追溯 |
| `legacy_analysis` | 只用于旧分析口径，不进入物理判据 |
| `unclosed` | 当前缺少的真实物理输入 |

候选轴不会自动形成笛卡尔积；只有命名生成器或 protocol 明确组合时才形成设计集合。legacy design ID 只用于 provenance，不是当前 case ID。

## 12. 输出格式

标准 campaign 目录：

```text
<campaign_id>/
├─ manifest.json
├─ lineage.json
├─ config/original.json
├─ config/normalized.json
├─ validation.json
├─ events.jsonl
├─ cases.parquet | cases.jsonl
└─ paths/<case_id>/
   ├─ config.json
   ├─ summary.json
   ├─ validation.json
   ├─ path.npz                 # 可选
   ├─ trace.parquet | trace.jsonl  # 可选
   ├─ events.jsonl             # 可选
   └─ COMPLETE                 # 仅完整成功 case
```

case callable 产生的 canonical 物理 summary 最低保存版本、identity、模型层级、地形/几何版本、参数来源、单位、frame、假设、遗漏、适用范围、不能回答的问题、物理/数值/模型状态、残差、容差和逐刺数据。阵列另外保存 rank、range、equilibrium 和 stability 状态。`CampaignRunner` 持久化时再加入 `run_state`、运行时间和内存记录。

这些字段用于复现和读取程序输出，本文件不对具体仿真数值作分析。

当 `CampaignSpec.mode == "formal"`，并且每个 case 都设置 `parameters.output.level == "summary"` 时，runner 使用 SQLite compact store；该模式不保存逐 case 数组、trace 或 events。任一条件不满足时使用普通逐 case store。
