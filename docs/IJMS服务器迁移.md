# IJMS Windows 离线服务器包

2026-09-11：本机生产批次已自然暂停，4149例入账：完整1567、预算停止1639、轴向范围停止339、数值停止577、执行错误27。自动接续及Codex定时监控均已关闭。服务器运行由用户手动启动，不再使用8小时分波入口。

## 使用

1. 把整个 `IJMS_Server_Package` 文件夹复制到服务器内置硬盘，路径可变，不要拆分子目录。也可以直接从移动固态运行，但运行时不能拔盘。
2. 双击 `START.bat`，自动打开本机浏览器运行台。不需要联网、安装Python、Conda或显卡驱动。
3. 正式批次模式：本次新增case数填0表示处理全部剩余147051例；填100表示在现有断点基础上再处理100例。按冻结队列顺序执行，不将任意前N例当作完整全因子设计。
4. 并发数填0自动使用逻辑CPU，受可用内存限制；也可手动调低。每worker的BLAS只用1线程。超过61个worker时使用多个进程池，按Windows处理器组分布工作线程。
5. 双击 `TEST.bat` 打开独立测试模式，默认4例，可选1至32例。实际计算完整10 mm路径，仍可能预算/范围/数值停止；结果保存在 `data/tests/时间戳`，不写入正式结果。
6. 页面提供本次进度条、预计剩余时间、处理速度、完整/停止/错误数量、CPU并发及内存磁盘余量。预计时间要等新结果积累后才出现。
7. 点击“停止新增派发”后，等页面显示已暂停、在途为0，再关闭控制台或移动文件夹。关闭浏览器不会停止求解。断电或意外退出后重新打开START并接续，已入账case不会重算；文件完整但未入账的结果直接补账。

## 数据与环境

源码仓库为 `https://github.com/Persenz1/Spine_Sim.git`。笔记本可clone后修改，修好后把对应源码同步到离线包的 `program/` 目录，保留同级 `runtime/` 和 `data/`。单独clone不包含Python、地形和正式结果；不要直接用旧生产入口中的本机绝对路径启动服务器。运行中不替换力学代码后继续混入同批次。

- `runtime/`：可移动的Python 3.13.13及原环境依赖（NumPy 2.5.1、SciPy 1.18.1等），通过相对路径隔离，不依赖原C/D/E盘环境。
- `program/`：源代码、既定配置、说明、原始材料数据及测试代码。运行主入口是 `program/scripts/run_ijms_portable.py`。
- `data/production_151200/`：原正式地形、冻结配置、4149例SQLite入账记录、4122份JSON.gz结果和CSV。27例执行错误没有轨迹文件，其错误文本在SQLite中。
- 地形共有20张原始高度图、20份原始元数据、40张包络。全部预存，运行中不生成地形；缺失输入直接报错，不回退CPU。原始历史地形的生成标签保持不变。
- `data/production_151200/results/summary.csv`：每次任务自然结束后导出的总表。结果JSON.gz保留轨迹、预载失败尝试、实际落点和checkpoint。
- `data/server_status.json`：服务器入口当前状态；`data/launcher.stderr.log`：启动及进程异常日志。
- `data/production_151200/batch_status.json`及原waves表是迁移时的旧入口记录；服务器运行台以server_status和case ledger为准，不读取旧8小时截止时间。

使用原物理实现、参数、单case CPU预算及预载换点规则；没有把提前终止或错误改写为成功。无GPU运行依靠完整现有地形，不表示地形可在CPU上重建。

可用内存低于2 GiB或磁盘低于20 GiB会停止新增派发并自然收尾。自动并发按每worker约0.75 GiB和预留3 GiB估算；内存较少时不会强行启满所有逻辑CPU。

当前结果体积推算：151200例压缩结果约15～18 GiB，加地形和环境约27～32 GiB；后续复杂工况可能更大。建议服务器目标盘至少留50 GiB空间。

本地离线包验证：包内Python独立导入、冻结输入读取、两worker实际求解2例（均完整，约43秒）、结果保存及网页显示。未在目标服务器实测，也未实测超过64逻辑CPU的机器；多处理器组支持是实现能力，不能据此保证目标机持续100%CPU占用。
