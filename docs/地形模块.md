# 地形模块

## 1. 模块作用

地形模块把解析配方、材料 profile 或实测文件转换成带明确网格、单位、有效性和来源记录的 2.5D 高度场，并派生有限球尖可达包络和一维 track。

主要源码：

```text
src/spine_sim/terrain/
├─ models.py               配方、区域、track 和 campaign 区域模型
├─ random_field.py         坐标可寻址随机场
├─ analytic.py             解析夹具
├─ api.py                  材料地形统一 API
├─ material_generators.py  砂纸、红砖、混凝土生成器
├─ material_profiles/      材料配置
├─ measured.py             实测表面导入、重采样和轻量规则高度图
├─ envelope.py             有限球尖包络和杆体 clearance
├─ library.py              本地地形库
├─ descriptors.py          描述量
├─ validation.py           地形比较和绘图数据
├─ plotting.py             地形视图
└─ cli.py                  spine-terrain 命令
```

本模块不计算单刺接触力，也不支持倒悬孔洞、多值侧壁或损伤后的实体拓扑。

## 2. 数据表示

### `TerrainRecipe`

定义一个可识别的地形 realization。两种 generator：

- `defined_geometry`：坐标可寻址随机场；
- `material_hybrid`：已经解析为 measured 或 synthetic 的材料生成模式。

主要身份字段包括 generator 名称/版本、seed、全局原点、canonical/production 网格、粗糙度目标、相关长度、核定义和材料 profile hash。

所有 `TerrainRecipe` 都要求 production spacing 恰为 canonical spacing 的两倍；间距数值本身可配置，默认值是 canonical 5 µm、production 10 µm。

### `RegionSpec`

定义一个节点居中、包含两端边界的矩形区域：

- `origin_x_m/origin_y_m`；
- `size_x_m/size_y_m`；
- `resolution_x_m/resolution_y_m`；当前实现要求二者相等，即各向同性网格；
- `purpose`；
- 内容寻址的 `region_id`。

数组 shape 为：

\[
(n_y,n_x)=
\left(\frac{size_y}{dy}+1,\frac{size_x}{dx}+1\right).
\]

高度数组顺序统一为 `[y,x]`，单位为 m。

### `Terrain`

材料/实测 API 的内存结果，包含：

- `height: float32[y,x]`；
- `dx/dy`；
- `valid_mask`；
- material、subtype、seed；
- generation、profile、source、measurement 和 grid metadata；
- 可选不确定掩膜和上下几何界。

### `TrackGeometry`

沿固定 y 的一维有限球尖几何，保存：

- track/recipe/region identity；
- 球半径、y 坐标和分辨率；
- 球心包络高度与 x/y 坡度；
- top-1/top-2 support 及原始节点 identity；
- surface、envelope、contact 三类法向；
- footprint、valid、near-tie、feature-switch 和 uncertainty mask；
- 可选包络上下界；
- 来源高度、mask 和 measurement semantics hash。

## 3. 定义随机场

`defined_geometry` 的生成链：

```text
seed + 全局 canonical 索引 + generator version
  → coordinate_noise
  → 有限可分离高斯核
  → canonical 节点（默认 5 µm）
  → production 偶数索引 stride-2（默认 10 µm）
  → 分 tile 写 raw_height.npy
```

噪声由全局节点直接寻址，不依赖请求窗口。相同 recipe 下：

- 小窗口等于大窗口相同区域的裁剪；
- 相邻 tile 的重叠节点相同；
- tile 行数不改变最终地形；
- 10 µm 节点等于 5 µm realization 的 `[::2,::2]`。

`compute_campaign_region` 根据拖动长度、最大阵列尺寸/间距、安装投影、弹簧行程、梁位移、针尖半径、杆体 clearance 和随机滤波 halo 推导所需区域，而不是硬编码一个固定矩形。

## 4. 材料生成

统一入口：

```python
generate_terrain(
    material=...,
    subtype=...,
    size_x_m=...,
    size_y_m=...,
    resolution_m=...,
    seed=...,
    mode="synthetic" | "measured" | "auto",
    measured_path=...,
    backend="cpu" | "cuda",
)
```

### 砂纸

- 本地存在适用实测源时：抗混叠重采样、有效补丁选取、重叠误差选择、raised-cosine 拼接、有界 PSD 残差和分位匹配；
- 没有适用源时：使用 granular fallback；
- P40、P100、P240 为单样本 `partially_validated`；
- 其他 grit 为 `provisional`。

### 红砖

组成：

```text
base + directional texture + irregular pores + fine roughness
```

当前 profile 是材料特定工程先验，状态为 `provisional`。

### 混凝土

组成：

```text
mortar + aggregate + void + finish + fine roughness
```

支持多个 finish subtype，当前都为 `provisional`。

### mode 处理

- `synthetic`：直接进入材料生成器；
- `measured`：实测源、范围或分辨率不满足时明确报错；
- `auto`：先尝试 measured，失败时重置同一个 PCG64，再生成与显式 synthetic 逐位一致的结果，并保存回退原因。

measured 路径使用 CPU；synthetic 可选 CPU/CUDA。metadata 记录请求后端、实际后端、provider、版本和设备信息。

## 5. 实测表面导入

`load_measured_surface` 支持：

- Hirox CSV；
- NPY、CSV、TXT 规则矩阵；
- XYZ 点；
- ASCII PLY；
- ASCII/二进制 STL；
- 安装可选库后的部分 x3p、sdf、os3d。

点云和 mesh 被栅格化为 2.5D 上包络，后续不再保留一般三维拓扑。

导入流程：

1. 读取并转换原始单位；
2. 建立显式 invalid mask；
3. 按配置处理 zero 语义和无效边界安全带；
4. 以有限占位值保存数组，同时保留真实 mask；
5. 默认使用稳健刚体平面拟合去倾斜；
6. 随机裁剪时限制无效比例；
7. 降采样前做箱式抗混叠，再双线性重采样；
8. measured 模式拒绝把低分辨率数据上采样成更高测量分辨率。

当前导入通常只能声明 `unknown_probe`，没有测量探针反卷积、确定性重建 mask 或可靠几何上下界。

## 6. 轻量高度图入口

`measured.py` 中的 `FileHeightMapSource` 只处理全有限 NPY/CSV/TXT 规则高度图。它登记绝对路径、原始单位、原点、spacing、shape 和文件 hash，不复制源文件。

`sample_file_heightmap` 返回内存采样数组和处理记录。它与 `load_measured_surface` 共属一个模块，但不会自动接到 `TerrainLibrary` 的统一注册流程。

## 7. 材料粗细网格

材料生成不是坐标可寻址随机场。对相同 seed 分别调用 10 µm 和 5 µm，RNG 消费顺序可能因 shape/resolution 改变，不能视为同一 realization。

配对细化必须调用 `refine_material_terrain_same_realization`。它要求：

- 材料、subtype、seed、mode 和 profile 相同；
- 细网格 spacing 恰为粗网格一半；
- 物理范围一致；
- 粗节点逐位保留；
- 细节点加入材料特定残差；
- mask 和 uncertainty 继续传播。

## 8. 有限球尖包络

对表面 \(h(x,y)\) 和球半径 \(R\)，离散包络计算：

\[
H_R(x,y)=\max_{(\xi,\eta)\in D_R}
\left[h(x-\xi,y-\eta)+\sqrt{R^2-\xi^2-\eta^2}\right].
\]

实现保留 top-2 support，不在 near-tie 时强选唯一支撑。不同法向含义：

- `surface_normal`：原始支撑处表面法向；
- `envelope_normal`：唯一可微包络分支法向；
- `contact_normal`：由支撑点指向球心的球面径向。

`forward_cap_gate` 检查支撑是否位于给定针轴的可用球帽前方。`check_segmented_tip_rod_clearance` 沿球冠、锥段和圆柱杆离散采样并检查地形穿透；它是无碰撞门控，不是分布式杆体接触模型。

## 9. 地形库

```text
terrain_library/
├─ recipes/
├─ sources/
├─ regions/<recipe_id>/<region_id>/
│  ├─ raw_height.npy
│  ├─ valid_mask.npy               # 存在时
│  ├─ 其他 uncertainty/bounds 数组 # 存在时
│  ├─ metadata.json
│  └─ COMPLETE
├─ tracks/
└─ manifests/
```

`open_region` 返回只读 NumPy memory map。track 由 NPZ、JSON metadata 和完成标记组成；加载时校验 schema、identity 和来源内容 hash。

### 重建限制

`defined_geometry` 可以由 recipe 和 manifest 原样重建。

材料或实测 region 目前不能一概保证跨机器字节重建：

- 某些砂纸 synthetic 路径会根据本机是否存在原始扫描选择拼接或 fallback；
- 显式 `measured_path` 未完整进入 recipe identity；
- 细化 region 未完整记录父高度 hash 和细化算法。

因此删除材料/实测缓存前，必须确认原始来源、实际 generation method 和细化父数据仍存在。

## 10. 描述、绘图与验证

地形模块可计算：

- 高度均值、RMS、偏度、峰度和分位数；
- x/y ACF、PSD 和相关长度；
- 坡度统计；
- 峰/坑密度、尺寸和深度；
- 非有限值、异常尖峰、边界/镜像相关等伪影检查。

这些是描述量。`compare_topographies` 和 `validate-material` 没有统一物理 pass 阈值；没有实测 reference 时生成成功不等于材料得到实验验证。

`plotting.py` 中的 groove selection 和球落位服务图形展示，不是 `ContactCandidate` 求解器。

## 11. 主要边界

- 只支持单值 2.5D 高度场；
- 一般 mesh、倒扣和多值侧壁不支持；
- 测量探针反卷积未实现；
- 损伤后表面更新未实现；
- 杆体检查不产生接触反力；
- profile 状态不会因一次生成或绘图自动升级；
- CUDA 后端只属于地形生成，不属于单刺/阵列求解。
