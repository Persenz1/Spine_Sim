# 运行与使用

本文件只说明怎样安装、调用和读取程序产物，不分析仿真结果。

## 1. 环境

项目要求：

- Python 3.11 或更高；
- NumPy 1.26 或更高；
- 可选 `pyarrow>=15`：Parquet case index 和 trace；
- 可选 `matplotlib>=3.9,<4`：地形绘图；
- 可选 `cupy-cuda13x[ctk]>=14.1,<15`：CUDA 材料/随机地形生成。

以下命令假设 `python` 指向已安装本项目的环境，并且项目命令已经位于 `PATH`：

```powershell
python -m pip install -e ".[test,plot,parquet]"
spine-sim validate-env --output results
```

`validate-env` 只检查 Python、NumPy、CPU 后端和输出路径父目录，不代表 CUDA、绘图库、Parquet 或物理参数已经闭合。

## 2. 测试

```powershell
python -m pytest -q
```

需要缩小范围时：

```powershell
python -m pytest -q tests/test_single_spine.py
python -m pytest -q tests/test_array.py
```

文档不保存某次运行的通过数量；以当前测试输出为准。

## 3. 地形命令

### 查看配方所需区域

```powershell
spine-terrain region-report `
  --recipe examples/m1_defined_recipe.json
```

### 生成区域

```powershell
spine-terrain generate-region `
  terrain_library `
  examples/m1_defined_recipe.json `
  examples/m1_debug_region.json
```

命令输出包含 `terrain_recipe_id` 和 `region_id`。

### 生成有限球尖 track

```powershell
spine-terrain generate-track `
  terrain_library <terrain_recipe_id> <region_id> `
  --radius-um 50 --y-mm 0
```

CLI 当前把球半径限制为 50 或 100 µm；Python API 接受任意正半径。

### 生成材料地形

```powershell
spine-terrain list-materials

spine-terrain generate-material `
  output/P100_seed12345.npz `
  --material sandpaper --subtype P100 `
  --size-x-mm 3 --size-y-mm 1 --resolution-um 10 `
  --seed 12345 --mode synthetic `
  --library terrain_library
```

### 绘图和描述性验证

```powershell
spine-terrain plot-region `
  terrain_library <terrain_recipe_id> <region_id> output/terrain_views

spine-terrain validate-material `
  output/P100_validation `
  --material sandpaper --subtype P100 `
  --size-x-mm 3 --size-y-mm 1 --resolution-um 10 `
  --seed 123 --seed 456 --seed 789
```

`validate-material` 生成描述量和图，不内置统一物理验收阈值。

## 4. 候选几何调用

核心调用顺序：

```python
from spine_sim import CandidateCursor, query_next_candidate
from spine_sim.geometry import SpinePath, SpinePose, SurfaceState

surface = SurfaceState(
    track=track,
    region=region,
    height_m=height,
    source_valid_mask=valid_mask,
)
path = SpinePath.from_track(track, center_z_m=tip_center_z)
pose = SpinePose(tip_axis=tip_axis, normal_model="contact")

candidate, cursor = query_next_candidate(
    surface, path, CandidateCursor(), pose
)
```

若要得到确定的姿态相关杆体 clearance，`SpinePose` 还需提供球冠轴向长度、锥段长度、杆半径和外露杆长，并且 `SurfaceState` 必须带匹配 track identity 的原始高度与 mask。

## 5. 单刺调用

```text
SpineAcceptedState.initial
  → solve_single_spine(...)
  → 检查 trial.result 与 trial.committable
  → commit_single_spine_trial
```

调用者需要构造：

- `SpineGeometry`；
- `SpineMaterial`；
- `FrictionParameters`；
- `SuspensionParameters`；
- `SingleSpineTolerances`；
- `BaseMotion`；
- `ContactCandidate`；
- 上一 `SpineAcceptedState`。

不要原地修改 accepted state，也不要提交 nonconverged、model-limit 或 stale-revision trial。

## 6. 阵列调用

```text
SpineInstance[]
  + ArrayAcceptedState.initial
  + MixedControl
  → solve_array_equilibrium
  → 检查平衡、rank、range、稳定性和 committable
  → commit_array_trial
```

每根刺的 candidate、装配初始间隙和 `stable_engagement` 在进入阵列前准备。阵列迭代不会自动重新查询完整地形。

## 7. Campaign 配置

统一 CLI 读取 `CampaignSpec` JSON：

```json
{
  "name": "campaign-name",
  "module_version": "adapter-version",
  "callable": "package.module:run_case",
  "workers": 2,
  "mode": "small",
  "cases": [
    {
      "module": "array",
      "module_version": "physical-adapter-version",
      "parameters": {},
      "upstream_hash": "terrain-and-geometry-lineage",
      "terrain_version": "terrain-version",
      "tags": []
    }
  ]
}
```

`callable` 必须接收 `parameters, RunContext` 两个参数，并返回 `CaseOutput`。

通用 runner 只检查返回类型，不自动检查物理 summary。canonical adapter 应自行建立 `CanonicalResultMetadata`，并调用 `validate_canonical_summary`；该校验不要求运行态。`CampaignRunner` 在持久化成功或异常结果时加入 `run_state` 和运行资源记录。

`BaseCaseSpec.parameters` 是开放映射。配置作者或 campaign 生成器负责在构造 `BaseCaseSpec` 前完成字段和单位归一化；adapter/callable 负责验证 canonical 输入和物理闭合，但不能在运行时改变已经进入 case identity 的参数表示。

## 8. Campaign 命令

先验证通用 runner：

```powershell
spine-sim run-case `
  examples/smoke_campaign.json --output results
```

该 example 只验证 runner 和存储，不运行地形—单刺—阵列物理链。

其他命令：

```powershell
spine-sim run-campaign campaign.json --output results --workers 2
spine-sim resume campaign.json --output results
spine-sim retry-failed campaign.json --output results
spine-sim summarize results/<campaign_id>
```

语义：

- `run-case` 默认运行第一个 case，也可用 `--case-id` 选择；固定单进程和 `small` 模式；
- `run-campaign` 按 campaign worker 数或 `--workers` 执行；
- `resume` 跳过完整性复核通过的 case；
- `retry-failed` 只选择已有 `run_state=execution_error` 的 case；
- 任一 case 为 `execution_error` 时运行命令退出码为 1；
- `validate-env` 失败退出码为 2。

## 9. Canonical 示例边界

`spine_sim.examples.canonical_module:run_case` 展示怎样从 `SpineInstance`、阵列求解、canonical metadata 组装 `CaseOutput`。

它使用手工构造的解析平墙候选：

- 不经过真实地形库和 `query_next_candidate`；
- 参数标记为 `analytic_test_fixture`；
- 只用于 canonical 调用链和结果 I/O smoke；
- 不能作为已标定硬件模型。

## 10. 输出读取

标准 case 目录位于：

```text
results/<campaign_id>/paths/<case_id>/
```

读取 summary：

```python
import json
from pathlib import Path

summary = json.loads(
    Path("results/<campaign_id>/paths/<case_id>/summary.json")
    .read_text(encoding="utf-8")
)
```

读取 trace：

```python
from spine_sim.io import read_trace_table

rows = read_trace_table("results/<campaign_id>/paths/<case_id>")
```

不要只凭 `COMPLETE` 文件名判断完整性。`ResultStore.is_complete(case_id)` 会复核 summary、配置、数组、trace、events、validation 和 result hash。

只有 `mode` 为 `formal`，并且每个 case 都含有以下设置时，runner 才使用 `case_summaries.sqlite3`：

```json
{
  "parameters": {
    "output": {"level": "summary"}
  }
}
```

这种 compact store 不保存 arrays、trace 或逐 case events。读取时使用：

```python
from spine_sim.io.results import open_result_store

store = open_result_store("results/<campaign_id>")
```

`open_result_store` 根据 `manifest.json` 的 `result_storage` 选择存储；若 manifest 声明 compact store 但 SQLite 数据库缺失，会明确报错。不要假定 compact store 存在逐 case 目录。

## 11. 地形缓存维护

```powershell
spine-terrain delete-cache `
  terrain_library <terrain_recipe_id> <region_id>

spine-terrain rebuild-region `
  terrain_library <terrain_recipe_id> <region_id>
```

Windows 下删除前必须释放打开的 NumPy memory map。

`defined_geometry` 可以由 recipe 和 manifest 原样重建。材料/实测地形可能依赖本地原始扫描、resolved generation method 或细化父数据；删除这类缓存前先确认所需来源仍存在。详细说明见[地形模块](地形模块.md)。

## 12. 公共 API 范围

根包 `spine_sim.__all__` 公开：

- 配置、状态、frame、wrench 和 identity；
- `TerrainRecipe`、`RegionSpec`、`TrackGeometry`；
- 候选 cursor、path、pose 和查询；
- 单刺输入、accepted state、solve/commit；
- 阵列输入、控制、accepted state、solve/commit。

地形生成/库和参数 registry 的完整 API 分别位于 `spine_sim.terrain` 和 `spine_sim.parameters`。`read_trace_table` 由 `spine_sim.io` 公开；`open_result_store` 当前从 `spine_sim.io.results` 导入。
