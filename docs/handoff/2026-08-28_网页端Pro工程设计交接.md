## 已确定的边界

- 以后只维护这一套程序。原实现中凡与新版机理冲突的内容直接修正；不保留旧版生产
  程序、自动回退、双写结果或长期兼容层。
- 地形生成继续使用当前模块。当前数值近似地形足以推进；另一台电脑上的砂纸原始扫描
  暂不下载，未来只作为材料标定数据，不得成为架构或单刺/阵列开发的阻塞项。
- 权威数值实现以 CPU 为先。单刺事件、阵列活动集和小规模平衡不依赖 CUDA；只有性能
  剖析证明地形形态学或大批量独立计算受益时，才增加可选 CUDA 后端。
- 单刺和阵列必须完整实现。允许机理降级，但每次降级必须有显式 `model_level`、假设、
  参数来源、适用范围和输出能力；不能静默改公式或把缺参填成看似安全的大常数。
- 整爪不得绑定一种外形。它至少要覆盖四阵列组成的内收十字对爪、单刺组成的圆形内收
  盘，以及其他可内拉构型。几何/驱动拓扑负责定义组件位姿与内拉约束；单刺或阵列组件
  只通过统一的局部状态、wrench、切线和事件端口参与整爪平衡，整爪求解器不得了解其
  内部是“一根刺”还是“一个阵列”。
- 新版模块按职责命名为 `geometry / single_spine / array / claw / robot`，不要继续用旧软件
  与新理论含义冲突的 M0/M1/M3 包名表达物理层级。

## 当前工程判断

可继续使用的资产是 `core/io/runtime` 基础设施、地形库与有限针尖包络、批量 campaign、
试算状态与已接受状态隔离、逐站逐刺 trace，以及路径指标 `J+ / J- / Jnet`、载荷集中度
和严格配对分析。旧数据已经证明这些工具能发现刚度—抗拖—均载权衡、名义刺数与实际
承载数的差别、峰值与全路径效果的差别，以及固定总预载下的规模稀释。

当前 `m3_fast` 只是二维、固定 y 轨迹、共同背板仅解 z、固定步长的准静态降阶实现。
它缺少单刺容量/损伤、真实逐刺脱离—回弹—搜索—再挂接、三维力矩与背板转动、通用整爪
和整机稳定性；全阵列重新压合不能再解释为逐刺再挂接。`Neff` 还与新版活动刺数重名，
必须拆成 `n_active` 与分量化 `n_share_*`。旧单刺弹簧分支存在一次重算后未再次检查互补
条件的问题，迁移时必须用解析夹具修正，而不是把旧数值当真值。

## 设计必须形成的一条计算链

```text
terrain/geometry → contact candidates → single spine
                 → shared-pose array → topology-neutral claw → robot equilibrium/stability
```

同一条链应能通过显式模型等级退化到现有二维准静态特例，而不是调用一套旧内核。旧报告
只用于守恒、正号、状态语义、路径指标和配对趋势回归；因状态、容量和事件语义改变，不要求
新版逐点复刻旧力曲线。物理失败、数值失败、模型未覆盖和输入缺参必须分开记录。

## 请 Pro 交付的内容

输出一份可执行的“统一实现蓝图”，至少包含：

1. 现有目录到目标职责的迁移图，以及最终唯一 CLI/生产调用路径；
2. terrain→单刺→阵列→任意形态整爪→整机之间的最小数据契约、坐标系和单位；
3. 单刺状态/事件/容量、阵列活动集与重平衡、通用整爪拓扑和驱动约束的求解顺序；
4. 机理降级层级和参数溯源规则，并明确每一级能回答和不能回答的问题；
5. 从解析单刺夹具、阵列守恒与事件收敛，到整爪 wrench 和整机三类极限的验证矩阵；
6. 分阶段迁移顺序、每阶段可运行产物、旧冲突代码的删除门禁和最终删除清单。

设计时请优先裁决：首版三维阵列活动自由度、单刺损伤的首版保真度、事件定位与延拓方法、
整爪组件/驱动拓扑契约，以及整机准静态稳定的最小状态。不要给泛泛的“可扩展架构”建议；
每个接口都应对应当前主稿中的方程、状态或验证需求。
